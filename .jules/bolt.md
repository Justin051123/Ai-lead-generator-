## 2025-02-15 - Parallelizing I/O-bound web scraping in Python while preserving order
**Learning:** I/O-bound processes such as web scraping are bottlenecked by sequential HTTP requests and artificial delays (like `time.sleep(1)`). Refactoring the pipeline into a modular function (`process_single_lead`) and employing `ThreadPoolExecutor` with `executor.map` enables concurrent execution. This preserves the original Google Search relevance ordering while cutting down execution time by over 98% (a ~52x speedup in mock benchmarks, processing 5 leads in 0.1s instead of 5.5s).
**Action:** Always map sequential I/O operations into concurrent worker threads when search relevance or initial sequence ordering must be preserved, and remove sequential sleep intervals when scaling with concurrent requests.
